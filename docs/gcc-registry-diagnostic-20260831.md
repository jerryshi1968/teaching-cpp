## 如何理解结果

“停止请求未确认”不等于“下载一直在后台运行”。旧脚本等待临时任务结束后，在失败分支仍会发出停止请求；而它使用的 `--collect` 可以在失败退出后卸载临时单元，因此停止请求可能找不到已经回收的单元。这是结合代码的解释，仍需本次状态与进程检查确认。[systemd 252 的 --collect 说明](https://github.com/systemd/systemd/blob/v252/man/systemd-run.xml)

`registry` 的 HTTP **401** 表示未携带登录令牌时收到的认证挑战，可以说明这次 HTTPS 连接已到达仓库；它不表示镜像已下载或清单摘要已验证。认证接口 `auth` 的预期状态是 **200**。429、证书错误和连接超时分别记录，不混为同一种故障。[Registry API V2 入口与认证响应](https://distribution.github.io/distribution/spec/api/#api-version-check)

如果 IPv4 成功而其他方式失败，将根据具体错误准备仅作用于下载任务的修正，不直接修改系统 IPv6。如果各种方式均无法连接官方仓库，再选择其他交付方式；不会自动改用未经核验的镜像或关闭证书/摘要校验。

本次诊断不访问镜像层实际下载地址。即使认证和仓库入口通畅，也不能保证随后所有镜像层都能下载；仍需后续实际拉取和摘要核验。
