# C++ 青少年编程练习平台

面向 C++ 入门、GESP、CSP-J/S 课程与竞赛训练的在线练习和教学管理平台。首版已于 2026-08-31 部署到生产服务器：

- C++ 平台：<https://tigao123.com/teaching-cpp/>
- 原 p5.js 平台：<https://tigao123.com/teaching-p5js/>

两个平台复用现有账号、角色和班级体系；C++ 项目拥有独立的前端、业务后端、源码存储和受限执行服务。首版定位是课堂练习工具，不是正式赛事评测机。

## 核心功能

- 单文件 `main.cpp` 编辑，支持 C++14/C++17 高亮、缩进、行号、字体调整和源码下载。
- 项目与多层作品组管理：新建示例、重命名、移动、排序、复制和删除。
- 手动保存与 1.8 秒空闲自动保存，带浏览器草稿和多窗口版本冲突保护。
- 保存成功后才提交运行；支持一次性标准输入、编译诊断、输出、历史快照和停止任务。
- 全局最多 20 个未完成任务，每位用户最多 1 个，实际编译/运行并发为 1，按入队顺序调度。
- 教师查看本班学生代码、复制为自己的练习，并向班级学生分发相互独立的模板副本。
- 历史缓存最多保留 24 小时、每位用户最多 100 MiB；正式项目的当前源码不按一天删除。
- 复用原平台的注册和班级码入班流程，不增加教师审批、充值或 AI 扣费逻辑；AI 仅保留界面位置。

首版不包含文件输入输出、交互终端、多文件构建、断点调试、题库判题、AI 服务或运行内存峰值采集。

## 架构

| 组件 | 职责 | 当前生产部署 |
| --- | --- | --- |
| `frontend` | React / Vite / CodeMirror 工作台 | Apache 静态站点 `/teaching-cpp/` |
| `backend` | 身份衔接、项目管理、保存、队列、历史与教学 API | PM2，`127.0.0.1:5180` |
| `runner` | 编译、运行、取消和容器清理 | `cpp-runner` 用户服务，`127.0.0.1:5280` |
| MySQL | 项目、班级关系、任务和结果元数据 | 与原平台同机，按 `project_type` 隔离 |
| 源码存储 | 当前源码与不可变运行快照 | 独立于原 p5.js 存储目录 |

浏览器只访问 Apache；执行服务不对公网开放，内部令牌也不会下发给浏览器。编译容器和运行容器彼此分开，均禁止联网、删除全部 capabilities、启用 `no-new-privileges` 和只读根文件系统。

当前代码中的主要限制：

| 项目 | 编译阶段 | 运行阶段 |
| --- | ---: | ---: |
| 内存 | 512 MiB | 256 MiB |
| PID | 64 | 16 |
| CPU 时间 | 15 秒 | 3 秒 |
| 墙钟时间 | 20 秒 | 5 秒 |

源码最大 128 KiB，标准输入和总输出分别最大 256 KiB。服务器上的 `cpp-runner` 账号还受 1 GiB 内存、1 核 CPU、256 个任务和禁用 swap 的总限额保护。

## 本机开发

需要 Node.js 22.12 或以上，推荐使用仍在维护的 Node.js LTS。

```powershell
Set-Location G:\teaching-cpp
npm install
npm run dev
```

打开 <http://127.0.0.1:5174/teaching-cpp/>。

本机默认使用演示模式：无需 MySQL，可以切换示例教师和学生，数据索引在内存中，源码快照写入 `storage/demo`，重启后重置。演示模式不会伪造 C++ 结果；点击运行会明确提示真实执行未启用。

也可以运行构建后的单端口演示：

```powershell
npm run build
npm start
```

打开 <http://127.0.0.1:5100/teaching-cpp/>。演示身份无需密码，只能在本机使用，不要把演示端口代理到公网。

## 配置

- 业务后端配置参考 [`.env.example`](.env.example)。
- 执行服务配置参考 [`.env.runner.example`](.env.runner.example)。
- 不要复制原平台的完整 `.env`，也不要把数据库密码、登录令牌、执行服务令牌或服务器备份提交到仓库。
- `APP_MODE=test` 只允许连接名称以 `_test` 结尾的测试库；生产写入与运行均需要显式开关。
- 后端与执行服务必须使用同一个固定编译器镜像 SHA256 ID。

生产端口可以通过环境配置调整；示例文件使用 `5200`，当前生产执行服务实际使用 `5280`。

## 检查

```powershell
npm run check
npm test
npm run build
npm run db:migrate
```

`npm run db:migrate` 默认只打印迁移计划，不连接数据库。可选 MySQL 检查需要独立测试库；Linux 容器检查需要专用普通账号和隔离环境。自动化测试不能替代真实服务器、浏览器和课堂验收。

## 部署与运维

- 当前服务器的 Apache + PM2 部署说明见[部署指南](docs/deployment-apache-pm2.md)。
- API 和内部执行协议见[API 约定](docs/api.md)。
- 容器、镜像和生产发布的完整过程见[验证记录](docs/verification.md)。
- `deploy` 和 `docs` 中带日期的文件包含已执行步骤、失败记录和修正版，主要用于审计与恢复。除非按当前状态重新制定变更方案，否则不要直接重跑历史脚本。

服务器为 2 核 / 4 GB，和原 p5.js、Apache、MySQL 同机；SELinux 当前关闭。容器仍共用宿主机内核，因此应持续限制资源、保持依赖更新、保护私有备份，并在扩大课堂使用前完成负载和恢复测试。
