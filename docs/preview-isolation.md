# p5.js 作品预览隔离：本次核查与实施范围

日期：2026-08-31。C++ 网页、既有教师身份识别、班级与学生展示，以及原 p5.js 保存和预览已确认正常。正式库迁移和三个类别隔离模型已发布，不重复执行。当前 C++ 写入与运行仍关闭。

用户在服务器抽取一个现有作品的 HTTPS 响应，得到 HTTP 200、Content-Type 为 text/html，未返回 Content-Security-Policy。结合已经核查的同源作品路径、允许脚本与同源权限的 iframe，以及共享 localStorage 登录令牌，这是需要处理的登录边界风险；不是已发现账号泄露或攻击记录。单个样本不能代表全站每个响应。

## 本地比较结果

在本机使用现有 p5-1.11.13 库、虚拟页面、图片和 JSON，在两个随机回环端口验证浏览器行为。没有连接正式站点或数据库，没有读取、写入、枚举或删除浏览器存储键值，只检查 Storage API 是否可用。完整结果在 `compat/preview-isolation-20260831/evidence.json`。

| 方式 | 作品可读取父页面虚拟标记 | 作品 Storage API | p5 画布 | 相对图片与 JSON |
| --- | --- | --- | --- | --- |
| 原同源方式：allow-scripts + allow-same-origin | 可以 | 可用 | 正常 | 正常 |
| 同源作品加 CSP sandbox allow-scripts | 不可以 | 被拒绝 | 正常 | 加载失败 |
| 严格 CSP 沙箱，再给公开素材增加 CORS | 不可以 | 被拒绝 | 正常 | 正常 |
| 独立预览来源 | 不可以 | 可用 | 正常 | 正常 |

四组结果均符合预期；“原方式符合预期”表示成功重现缺少隔离，不表示安全。另行直接打开严格沙箱加 CORS 的页面，画布、图片、JSON 正常，Storage API 仍被拒绝。

两个本机端口仅模拟不同来源，不等于真实子域名、证书或 Apache 发布通过。音频、摄像头、全部旧作品和跨来源坐标桥接尚未实测。浏览器未读取真实登录信息，也没有执行真实学生作品。

## 建议采用独立作品预览子域名

建议预览域名为 `preview.tigao123.com`，继续使用现有同一台服务器及 Apache。两个平台的入口保持 `https://tigao123.com/teaching-p5js` 与 `https://tigao123.com/teaching-cpp/`，账号、班级码、数据库、余额和 p5.js AI 业务不改变。

作品文件继续保存在 `/var/www/teaching-p5js-backend/storage/projects/`，无需搬迁或复制学生源码。新域名只提供作品和必要静态素材，不提供登录、公共 API、数据库、PM2 或 C++ 执行服务。不复制主站整个 DocumentRoot，不将 `/api` 代理到预览域名，不把公共令牌交给预览页。

直接给原路径增加严格沙箱虽然少改配置，但会改变作品浏览器存储、资源访问及部分受限功能；当前原编辑器的坐标显示也依赖直接读取 iframe 文档。不能把它作为不影响功能的一行修复，也不能在原同源 CSP 中加回 allow-same-origin 后宣称隔离完成。[CSP sandbox 标准](https://www.w3.org/TR/CSP3/#directive-sandbox)、[HTML iframe 标准](https://html.spec.whatwg.org/multipage/iframe-embed-object.html#attr-iframe-sandbox)

## 后续修正范围与验收要求

1. 为预览子域名建立独立的 Apache 站点与 HTTPS 证书。优先使用证书工具的仅签发模式，不让工具自动重写已有主站配置；先核查服务器现有证书工具和续期方式。
2. 在预览站点映射现有作品目录及必要的 `/teaching-p5js/libs/`、音频素材路径。已确认项目使用这两种公共绝对路径；服务器 sound 目录尚未核查，不假定所有素材都放在作品内部，也不代理整个主站来掩盖路径问题。
3. 主站旧 `/teaching-p5js/projects/` 地址必须统一转到预览来源，覆盖直接访问、HTML、SVG 和其他可执行文档；不能只改编辑器 iframe，让旧地址继续同源执行学生内容。跳转前须验证新站点可用，失败时保留写入和运行关闭。
4. 原 p5.js 编辑器只调整预览入口和坐标通信，保留保存、AI、班级与作品管理流程。坐标通信采用只接收当前预览窗口、固定预览来源、有限数值字段的 postMessage；不得接受执行脚本、HTML、任意网络请求或读取登录信息等指令。为不改写已有学生 HTML，可评估在独立预览来源增加受限预览外壳；此桥接尚未实现。
5. 图片、音频、字体、JSON、相对路径、公共绝对路径、编辑器内预览、独立大视窗及直接旧链接都要回归。必要的跨来源读取只对无凭据静态资源开放，不能放宽公共认证 API 的跨域权限。
6. 登录令牌只保留在主站来源；禁止传到 URL、预览窗口或预览域名存储。若作品使用了旧来源的本地游戏进度，新来源不会自动拥有旧值；不可整体复制主站 localStorage，否则会把登录信息也带入作品来源。此类旧进度迁移需要单独列出允许的游戏数据键。
7. 不通过 document.domain 放宽主站与预览站点的来源边界。核查 Cookie 的 Domain、公共 API 的 CORS、旧作品入口与其他映射，避免绕回主站。新预览站不得设置共享登录 Cookie；独立子域名仍属于同一站点，不能把 SameSite 当作两者之间的隔离。
8. 预览来源本身不承载可信用户身份。共享该预览来源的学生作品之间仍不是强隔离；不要在该来源存放私密信息。将来需要作品互相隔离时，另行设计每作品来源或更严格沙箱。
9. 新配置及前端先备份、核验原文再发布；保持全部已有注释与无关原文。`G:\teaching-p5js` 的本地旧模型不得覆盖生产中已发布的三个隔离模型。当前 C++ Apache 引用及已发布版本文件保持不变。
10. 本地隔离比较已完成，但真正的预览修正尚未发布。正式上线仍需验证原作品行为与隔离边界，再开放 C++ 新建/保存；真实编译运行继续作为下一阶段。

## 现在只做 DNS 准备

本次通过本机 DNS 查询得到域名的权威服务器为 `dns27.hichina.com`、`dns28.hichina.com`，与阿里云解析相符；这不能证明用户当前登录的是哪个管理账号。`preview.tigao123.com` 的 A 查询返回 NXDOMAIN，是当时本机解析器结果，不替代控制台的既有记录检查。

进入管理 `tigao123.com` 的阿里云云解析 DNS 控制台，在公网权威解析的域名解析设置中新增以下一条记录；若已有同名记录，先核对，不覆盖。

| 字段 | 填写 |
| --- | --- |
| 记录类型 | A |
| 主机记录 | preview |
| 解析请求来源／线路 | 默认 |
| 记录值 | 当前这台 Linux 服务器的公网 IPv4；与当前主站直接指向该服务器的 A 记录一致 |
| TTL | 默认 10 分钟（600 秒） |

只增加 preview，不改动 @、www、邮件或其他现有记录，不增加通配符或开启新的 CDN/WAF。若主站原记录经过 CDN/WAF，不直接复制其边缘地址；应使用服务器控制台中的公网 IPv4。操作方式见 [阿里云添加解析记录](https://help.aliyun.com/zh/dns/pubz-add-parsing-record)。

新增 A 记录不会完成 HTTPS 或作品隔离，暂时不要在新域名登录、预览作品或绕过证书警告。无需先修改 `.env`、Apache、服务器防火墙或 PM2；后续核对 DNS，再安排证书和独立站点。此文和本地实验文件不要上传到公开目录，它们不是可直接运行的生产发布包。
